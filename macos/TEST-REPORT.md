1.2.0.2 改为 ARM 原生运行并减少界面刷新与后台查询后，测试者反馈流畅度明显改善。最终构建再次从 Steam 启动：

- Steam 日志记录调用 Mod 脚本并传入原游戏路径，无需手动启动器。
- 系统进程采样确认 ARM64，父进程为 Steam。
- BepInEx 加载 MusicBridge 1.2.0.2，22/22 个 Harmony 游戏挂钩成功。
- 音乐面板与底栏控制绑定，网易云登录状态从钥匙串恢复为 Connected。
- 清理社区分支里无关的 Valheim 检测后，误导性包名及 Game type not found 警告消失。
- 检查时未发现插件 Error/Fatal/Exception。游戏原生 TMP 字体下划线缺字警告仍存在。

没有同场景 FPS 基准，不能把主观流畅度反馈当作定量性能结果。

## 长时间运行中发现的音频设备问题

后续实际运行中出现网易云进度继续前进、整个游戏无声。Unity 日志记录默认设备变化、FMOD 输出设备初始化失败，以及退回 emulated software output with no sound。该问题不能用之前的启动成功结果排除。

1.2.0.3 增加输出失败日志检测、延迟限次恢复和“修复游戏声音”按钮，恢复时尝试保留网易云曲目、进度和暂停意图，并重新解码运行时音频。失败重试在任意 60 秒内最多三次，不修改系统音量或默认设备。新增回归覆盖正常状态不重置、延迟去抖、重试退避、次数上限、手动重试和迟到的驱动错误。

依据：[Unity AudioSettings.Reset](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/AudioSettings.Reset.html)、[Unity 音频设置](https://docs.unity3d.com/2022.3/Documentation/Manual/class-AudioSettings.html)。全局音频重置可能使播放状态和运行时创建的音频失效，因此不能只调用 Reset 而不恢复播放。

自动测试不能确认扬声器实际出声；该修复需要额外的实际游戏音频验收，不保证能够修复持续不可用的硬件或驱动。

1.2.0.3 实机验证发现普通设备切换的中间警告也可能在 Unity 自行恢复前出现。因此 1.2.0.4 只把最终进入无声输出的错误作为自动重置条件；回归测试明确拒绝中间警告，避免重置循环。按试用反馈移除等待恢复的 UI 提示，只保留“修复游戏声音”按钮。

1.2.0.4 已通过 Steam 实际加载，22 个挂钩与网易云登录恢复成功，启动时未发现 FMOD 无声输出错误。等待提示已从代码中移除；此版本的设备切换后听感及进度保留仍需人工确认，不能将启动成功视为完整音频恢复验收。

1.2.0.4 实际试用后，测试者反馈“没问题了”，并要求补充恢复按钮的位置说明。README 已注明在音乐/歌单面板展开 Mod 区域后、音源标题下方。此反馈确认了本次使用体验，仍不能替代所有设备和长期稳定性的覆盖。
